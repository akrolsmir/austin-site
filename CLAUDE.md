# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Bun 1.3.14 + Node 24 (see `.nvmrc`). Use `bun add` / `bun add --dev` / `bun remove` for dependencies and commit `bun.lock`.

```sh
bun install --frozen-lockfile
bun run dev                    # next dev
bun run lint                   # eslint (next core-web-vitals + typescript)
bun run typecheck              # tsc --noEmit
bun test                       # all tests (tests/*.test.ts, written with node:test + node:assert, run by Bun)
bun test tests/notion.test.ts  # one file
bun test -t "fail closed"      # one test by name pattern
bun run build && bun run start # production build / serve
bun run db:push                # create/update the Neon tables from src/db/schema.ts (needs DATABASE_URL in .env.local)
EDITOR_DEV_OWNER=1 bun run dev  # act as the owner without OAuth (ignored when NODE_ENV=production)
bun run sync                   # mirror Notion → data/ (needs .env.local); --offline reconverts from the raw cache; --blob also pushes to the live Blob store
```

Local dev, tests, and builds need no env (without `BLOB_READ_WRITE_TOKEN` the site reads `data/`; `POSTS_SOURCE=local` forces that). Copy `.env.example` to `.env.local` only to run the sync; it throws visibly on any Notion/config error rather than writing a partial mirror.

Deploy: `vercel deploy` (preview) / `vercel deploy --prod` (production). Linked to `austin-proj/austin-site`. Vercel Cron (`vercel.json`, needs a Pro plan) calls `/api/sync` every 15 min and `/api/studio/tick` every 10, on production deployments only. Production env and one-time setup are in README → Deployment.

## Architecture

Next.js 16 App Router, React 19, Tailwind 4, TypeScript. Pages are server components. Client code is `src/components/editor-loader.tsx` (the only editor code visitors download; it imports `src/editor/` when the `editor=1` hint cookie is present), the `/studio` UI (`src/app/studio/studio.tsx`), and `/sign-in`. `next.config.ts` sets `agentRules: false` so `next dev` leaves this file alone; still read `node_modules/next/dist/docs/` before using a Next API, since Next 16 differs from older versions (e.g. error boundaries get `retry`).

**Content pipeline (Notion → Blob/repo → site).** Notion is the source of truth; pages never call Notion. `src/lib/sync.ts` is the one sync core, run by `/api/sync` (Vercel Cron GET or Notion button POST, against the Blob store) and by `scripts/sync.ts` (against the committed `data/` snapshot, optionally pushed to Blob with `--blob`). Stores stage writes and persist them only in `commit`. In Blob, `site/raw/*.json` and `site/posts/*.md` are content-addressed and the index is a never-overwritten pointer file `site/index/<seq>-<tag>.json` (written last with `allowOverwrite: false`, newest found by `list()`, because public Blob reads are CDN-cached and an overwritten file reads stale; `readPointer`/`writePointer` in `src/lib/posts.ts`), which is the single commit point; the index records the deploy's commit so a new build reconverts from the Blob raw cache. The route is open; calls without a valid `Bearer CRON_SECRET` (constant-time compare) skip while the index's `syncedAt` is under 60 s old. It stops fetching after 180 s (rest reported `pending`), and `revalidatePath`s `/`, `/posts`, and changed/removed slugs. `src/lib/posts.ts` reads Blob when `BLOB_READ_WRITE_TOKEN` is set (index from origin, markdown via CDN, memoized by content key) and falls back to `data/posts` otherwise or when the index is missing; Blob read errors throw. The core uses `src/lib/notion-client.ts`, a dependency-free Notion REST client (`createNotionClient(env, fetch)` takes injected env and fetch so tests mock it) that queries the Posts data source with a mandatory publish filter, paginates fully, throttles serially, retries 429/5xx with bounded backoff, and recursively fetches block children without descending into `child_page`/`child_database`. For the snapshot, the sync writes `data/posts-raw/<id>.json` (catalog entry plus block tree; refetched only when `last_edited_time` changes), uploads Notion-hosted files to Vercel Blob and stores only the Blob URL in the cache, records each image's intrinsic width/height on its `file`/`external` source (fetched once via `image-size`, also in `--offline` mode), then converts each raw file with `src/lib/notion-markdown.ts` into `data/posts/<slug>.md` (JSON-string frontmatter, see `src/lib/posts.ts`). Files for unpublished pages are deleted. Image dimensions travel as the markdown image title (`![caption](url "WxH")`). `src/components/prose.tsx` renders bodies with `marked` plus `html-react-parser`, swapping sized `<img>` tags for `next/image` (Blob hosts optimized via `images.remotePatterns` in `next.config.ts`, other hosts `unoptimized`, unsized images left as plain `<img>`); `/posts/[slug]` prerenders every post via `generateStaticParams` and uses ISR with `dynamicParams = true`, so new slugs render on demand and removed ones revalidate to 404. `/writing` and `/writing/[id]` are permanent redirects for the earlier id-based URLs.

**Fail-closed invariants worth preserving.** `publishFilter` throws on a missing or malformed `NOTION_PUBLISH_FILTER` rather than querying unfiltered. The client also drops archived/trashed and future-dated pages regardless of filter. Truncated query results (`request_status.type === "incomplete"`) throw rather than yielding a partial index, which matters because the sync prunes posts absent from the index. Nothing is committed to either store if any step throws, and a failed sync (or unreadable index) returns a generic 500 without writing `syncedAt`. Error messages never include response bodies or tokens. `safeUrl` in `src/lib/types.ts` only allows http/https/mailto. The converter escapes markdown/HTML characters in Notion text so committed markdown carries no raw HTML from Notion; `marked` renders it without sanitization on that basis. Never hand-edit `data/` or the Blob `site/` prefix; the sync regenerates them.

**Editable site (contract and as-built notes: `docs/editable-site.md`; operations: README → Editable site).** Slots (`src/site/schema.ts`, defaults in `content.json`/`theme.json`, read through `getSite()`, rendered with `<E>`/`data-e`, theme as CSS variables in the root layout) are the only editable surface. The overlay (`src/lib/overlay.ts`) holds published values that differ from defaults: immutable versions under `site/overlay/` plus a head committed with the same pointer scheme as the posts index; `overlayStore()` has `read/publish/revert/prune`, and callers revalidate (`revalidatePath("/", "layout")`). Auth is Better Auth with GitHub (`src/lib/auth.ts`); `getOwner`/`requireOwner` are the only auth API, and only the GitHub id `OWNER_GITHUB_ID` is the owner. Neon + Drizzle (`src/db/`; tests use PGlite, data functions take `db`). The editor (`src/editor/`: `store.ts` state and server calls, `dom.ts` page wiring, `app.tsx`/`controls.tsx` chrome, `draft.ts` pure logic) keeps a draft in `localStorage` and publishes through `/api/overlay`. `/studio` (`src/app/studio/`, JSON contract at the top of `src/lib/studio/types.ts`, routes in `src/app/api/studio/handlers.ts` with injected deps) is a public read-only chat where the owner's messages start runs: the fast lane (`src/lib/studio/fast.ts`, an Anthropic tool loop that answers or publishes overlay values) and the code lane (`src/lib/studio/code.ts`, `sandbox.ts`, `github.ts`, `scripts/studio-runner.ts`: Agent SDK in a Vercel Sandbox, then a PR committed by the server). There is no worker: a throttled `tick` on studio reads plus the `/api/studio/tick` cron reaps, sweeps, and drains the queue in `after()`, within function deadlines.

**Editable-site invariants worth preserving.** Every write route calls `requireOwner`, requires JSON, and rejects cross-site requests; reads never return private threads/messages, `context`, or logs to a non-owner. Slot values are validated by `validateValue` on client and server and rendered only as React text or CSS variable values, never as HTML. Blob commit points are never overwritten (pointers); a lost race is a conflict, not an overwrite. An unreadable overlay renders defaults (`OverlayDamaged`) rather than taking the site down. The sandbox gets only `ANTHROPIC_API_KEY` and a per-run token (hash stored, valid only while its run is running); nothing it reports is trusted, and changed paths are re-read and checked. Code-lane PRs merge automatically only when every path is in `AUTO_MERGE_PATHS` (an allow-list: content/theme JSON and stylesheets) and the Vercel preview succeeded; everything else waits at `needs_publish` for the owner. Previews and `next dev` use their own data (`previewData` in `src/lib/types.ts`: a `preview` Postgres schema and `site/overlay-preview/`), sign-in is production only, `EDITOR_PREVIEW_OWNER=1` makes a preview's viewers the owner (behind Vercel's Deployment Protection), the code lane refuses to start outside production, and previews of `studio/*` branches keep the database and owner mode off. In production the origin comes from config, never the request. `?ask=` context is accepted only same-origin and reaches models as fenced, quoted text. `EDITOR_DEV_OWNER` is ignored in production. Every external call (Blob, Anthropic, Sandbox, GitHub) has a time limit, and error text shown to users never carries response bodies or tokens.

**Notion schema assumptions.** Posts database uses `Tags` (multi-select; `Draft` excluded by the filter), a `Date` formula property, and an `Excerpt` rich-text property. Property names are configurable via `NOTION_DATE_PROPERTY` / `NOTION_EXCERPT_PROPERTY`. Notion API version is pinned to `2026-03-11` and uses the `data_sources` query endpoint.

## Conventions

- Code is deliberately dense: single-line JSX, compact functions, few files. Match that rather than expanding into many small components.
- `README.md` is the authoritative operational doc (Notion rules, sync pipeline, deployment). Update it when behavior changes. `DEVLOG.md` holds Austin's roadmap notes.
- Editorial copy comes only from Austin's public Notion content or lorem ipsum. Intro, projects, and work on the homepage are placeholders (now slot defaults in `src/site/content.json`). Album photos are in Vercel Blob, listed in `src/lib/photos.json`, added with `bun run photo` (strips EXIF/GPS); see README.
